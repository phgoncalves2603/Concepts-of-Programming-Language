
# Project 2 – Lexical Analyzer and Recursive Descent Parser

## Overview
This project implements two fundamental components of a compiler:

1. **Lexical Analyzer (Lexer)** – converts an input arithmetic expression into tokens.
2. **Recursive Descent Parser** – verifies whether the sequence of tokens follows the grammar of valid arithmetic expressions.

The program reads an expression from an input file and checks whether it is syntactically correct according to the defined grammar.

---

## Features
- Integer literals
- Arithmetic operators:
  - Addition (`+`)
  - Subtraction (`-`)
  - Multiplication (`*`)
  - Division (`/`)
- Unary minus (e.g., `-5`, `-(3+2)`)
- Parenthesized expressions
- Operator precedence (`*` and `/` before `+` and `-`)
- Whitespace is ignored
- Syntax error detection with row and column information

## Lexical Analyzer

The lexical analyzer reads the input expression character by character and produces tokens.

Each token contains:
- Token type
- Lexeme
- Row number
- Column number

Supported token types:

- ADDITION (`+`)
- SUBTRACTION (`-`)
- MULTIPLICATION (`*`)
- DIVISION (`/`)
- LPAREN (`(`)
- RPAREN (`)`)
- INTEGER
- EOS (End of String)

Whitespace characters are ignored.

Example input:

```
(2*3)+4
```

Example token sequence:

```
LPAREN
INTEGER(2)
MULTIPLICATION
INTEGER(3)
RPAREN
ADDITION
INTEGER(4)
EOS
```

## Parser

The parser is implemented using **recursive descent parsing**.

Each non-terminal in the grammar corresponds to a method in the `Parser` class.

### Grammar

```
Expression        → Term Expression_Prime

Expression_Prime  → + Term Expression_Prime
                  | - Term Expression_Prime
                  | ε

Term              → Factor Term_Prime

Term_Prime        → * Factor Term_Prime
                  | / Factor Term_Prime
                  | ε

Factor            → ( Expression )
                  | - Expression
                  | Number

Number            → Int-Lit
```

The parser reads tokens from the lexical analyzer and verifies whether the expression conforms to this grammar.

If the expression is valid, the parser prints:

```
Parsing completed successfully.
```

Otherwise, a syntax error is reported.

## How to Run

### 1. Write an expression in `expr.txt`

Example:

```
(2*3)+4
```

---

### 2. Compile the project

```
javac lexer/*.java parser/*.java
```

---

### 3. Run the lexer (optional)

```
java lexer.lexerTest expr.txt
```

This prints the tokens generated by the lexical analyzer.

---

### 4. Run the parser

```
java parser.parserTest expr.txt
```

If the expression is valid:

```
Parsing completed successfully.
```

If there is a syntax error, the parser reports the location of the error.

---

## Error Handling

The program detects several types of errors:

- Invalid characters in the input
- Unexpected tokens
- Missing parentheses
- Incomplete expressions

Errors include row and column information to help locate the problem.
